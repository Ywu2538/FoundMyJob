# FoundMyJob

面向校招与社招的本地求职助手：真实岗位同步、多份求职画像、AI 简历生成与审核、导出以及投递跟踪。使用 Node.js 原生 HTTP + SQLite，使用本地 Word / PDF 解析依赖。首次运行前执行 `npm install`。

## 本地运行

推荐 **Node.js 24 LTS**，最低 22.13（需支持 `node:sqlite`）。

```sh
npm install  # 首次安装或更新依赖时执行
npm start
```

Windows 可双击 `Start-FoundMyJob.cmd`。它会独立在后台启动服务并打开 <http://127.0.0.1:4173>；关闭启动窗口或浏览器不会停止服务。重复双击会复用已有服务。需要停止时双击 `Stop-FoundMyJob.cmd`；有简历正在生成时会提示先等待完成。电脑重启后再次双击启动即可，不修改系统开机启动项。

`npm start` 仍是前台运行方式，需要保留终端，Ctrl+C 停止。后台日志在 `.runtime/background-server.log`。SQLite 在部分 Node 版本显示 ExperimentalWarning，不影响当前运行。

本版本需要后端，不能只把 `dist/` 上传到静态托管。默认（`FMJ_DEPLOYMENT=local`）仅监听 `127.0.0.1`，用于**单用户本机**；不支持公开暴露或多人共享实例。

### 统一入口部署（`FMJ_DEPLOYMENT=campus`）

挂在 SuperUnknown 统一入口网关之后，地址为 `/jobs/`（网关转发时去掉前缀，前端资源和接口都用相对路径）。此模式下：

- 监听 `0.0.0.0`，只应暴露在 Docker 内网，由网关先检查统一账号登录；没有 `X-User-Id` 请求头的请求一律返回 401（`/api/health` 除外）。
- 跨站校验按网关转发的 Host / `X-Forwarded-Proto` 判断，本机 Cursor 不可用（服务器上的 Cursor 登录不能共享），生成简历请用自带 API Key 或自部署模型。
- **个人数据尚未按用户隔离**（SP-110 之前所有登录用户共用一份求职空间），仅适合演示或单人使用。

## 使用流程

1. 在「求职画像」新建或复制画像，例如「加拿大 · Data Engineer」「加拿大 · Software Engineer」「中国 · 软件工程师」。各自选择招聘地点范围（国内／国外／国内外均考虑），填写职位、简历语言和真实教育、技能、工作或项目经历。支持导入 Word（.docx / .doc）、PDF、图片、TXT / Markdown 文件；复制后两份画像独立编辑。
2. 在「发现岗位」选择搜索使用的画像，默认展示岗位库中的全部可浏览记录，按技能、目标职位和求职阶段计算匹配度；排序只改变先后，用户可主动选择地区、职位、来源筛选或显示数量。画像的地点偏好决定「继续查找岗位」提供国内、国外或两组官网入口。点击「同步真实岗位」从企业公开招聘板获取岗位；支持添加 Greenhouse / Lever 招聘板，也可以导入真实 JD 和原文链接。同步得到的岗位库共享，画像决定筛选和排序。
3. 在「AI 与数据设置」选择本机 Cursor，或自带 Key 的厂商与模型。
4. 在岗位详情确认生成使用的画像、语言及数据发送与额度使用，再生成简历。任务保存该画像的版本和事实快照；生成中编辑或切换画像不会改变这次任务。生成前画像已被其他窗口修改时，需刷新后重新确认。任务状态保存在「生成记录」，刷新不丢任务。
5. 编辑简历、逐项审核，然后导出 Markdown 或通过打印另存为 PDF。内容变化会使审核状态失效。
6. 自行到企业原文投递，在投递追踪中记录进度；后端要求同一岗位、同一画像有已审核简历才能标记已投递／面试中。简历、生成记录和投递记录显示来源画像，支持按画像筛选。岗位库卡片在任一画像有「已投递」「面试中」或「已结束」记录时显示绿色「已投递」标签，「准备中」不显示；进度更新后标签同步刷新。

旧版本的单份档案自动迁移为第一份画像，历史简历及其原有事实快照保留。画像可以归档、恢复；归档不删除简历和投递记录，至少保留一份可用画像。当前选择按浏览器标签页记住；切换时保留尚未保存的表单草稿，但搜索与生成只使用已保存的数据，关闭页面前请保存。

多画像属于当前本机求职空间；本版本仍没有在线注册或多账户认证。其他用户各自在自己的电脑运行，在线账户隔离需要在后续多人版本中实现。

点击侧边栏底部的用户卡片或右上角头像进入「用户中心」。用户名和头像独立于求职画像，切换画像后保持不变，点击「保存用户信息」写入本机数据库。头像支持最大 5 MB 的 JPG、PNG、WebP，自动居中裁成正方形并压缩为 256 × 256 的 JPEG；可移除头像或恢复已保存信息。「简历管理」直接打开全部画像的「我的简历」。下方显示当前画像，可切换并只编辑基础信息、专业技能和求职偏好；保存时保留原有教育、工作和项目经历。完整画像页中未保存的经历草稿也会保留，需回到完整画像页单独保存。

没有示例经历自动混入新数据库；旧 Demo 的浏览器记录可在设置中单独导出。

## 经历文件导入

在「求职画像」点击「导入经历文件」，选择 Word（.docx / .doc）、PDF、PNG / JPG / WebP / BMP 图片、TXT 或 Markdown，最大 10 MB。文件仅在本机内存解析，不保存原始附件，也不发送给 AI 服务。提取后左侧保留完整原文，右侧同时显示专业技能、教育、工作／实习、项目经历四个编辑框，并保留当前画像中已有的文字。可从原文选择段落，用 Ctrl+C / Ctrl+V 分别复制粘贴，也可点击对应栏目旁的「填入选中文字」在光标处插入或替换选中内容。可以反复整理多个栏目，原文不会被移走。点击「填入画像草稿」一次应用本次修改；取消不会改动画像。最后点击「保存当前画像」写入数据库。经历栏目各最多 12,000 字符；专业技能支持逗号、分号或换行分隔，确认时整理为技能列表，最多 50 项、每项 100 字符、总计 1,000 字符。超长会提示精简，不会静默截断。

PDF 最多 100 页；无文字或文字很少的页自动用本地 Tesseract OCR（简体中文 + English）识别，每次最多 OCR 20 页，加密 PDF 需先解锁。Word 使用结构化 XML 读取正文、表格、页眉页脚和文本框，并处理前 20 张嵌入图片中的可识别文字。导入界面只展示提取文字和经历编辑栏，不展示嵌入图片或图标。扫描图片直接识别。OCR 和语言包随 npm 依赖安装，识别时不访问云服务；首次使用在 `.runtime/ocr-languages/` 准备本地语言包。OCR 结果必须核对人名、数字、日期和阅读顺序；装饰图形不推断为个人经历。TXT 支持 UTF-8、带 BOM 的 UTF-16 和 GB18030 中文编码。空文件、损坏文件和扩展名不匹配会提示错误，保留已有经历。

打开根地址 `http://127.0.0.1:4173/` 默认进入工作台；明确带 `#jobs` 等页面锚点的链接仍打开对应页面。

## 经历对比

岗位详情提供「经历对比」按钮，点击后在独立小弹窗中加载三列表格：岗位要求、我的经历、判断。相关经历和简短判断说明直接展示，无需展开；判断分为绿色对勾「符合」、黄色感叹号「部分符合」、红色叉号「不符合」。弹窗可切换对照画像，查看必须条件、加分条件和重要性未注明的条目。关闭弹窗返回原岗位详情，保留滚动位置、生成画像、语言与确认选项。支持刷新对照和跳转补充画像，中文和 English 界面均可使用。详情中的「办公方式未注明」指原文未明确提供现场、混合或远程办公安排。

第一版通过本机规则比较已保存的原文，不调用模型或消耗生成额度，也不修改现有排序分数。工作或项目中的明确实际使用记录可标记「符合」；仅列出技能、正在学习、缺少经历或包含额外资格条件时显示「部分符合」并说明待确认的内容。只有原文明确否定相关经历，或可直接比较的总工作年限低于要求时，才标记「不符合」。不从未填写内容推断能力缺失，不累加项目时长或不完整日期。专业程度、行业场景、复杂替代资格及未识别条件需要人工核对；本机规则不是完整的语义资格审核。

摘要岗位明确提示覆盖有限；最多展示 60 条识别到的要求。对照使用已保存画像，草稿修改会提醒先保存。`POST /api/jobs/match` 接收 `jobId`、`profileId`、`profileRevision`，按服务端最新岗位和指定画像计算，返回原文位置、画像版本及岗位内容摘要值；画像版本过期返回 409。每次打开或刷新重新计算，不保存可能过期的判断。

## 界面语言

右上角可选择中文 / English，刷新后保留浏览器偏好。界面语言独立于画像和简历生成语言；个人经历、岗位原文、公司名称和简历正文保持原文。切换语言会保留画像草稿与搜索条件。

## 本机 Cursor

在「AI 与数据设置」选择 Cursor，点击「检测并连接」。已有 CLI 和登录会直接复用；Windows 未安装时点击「安装连接工具」，从 Cursor 官网获取官方包。然后点击「Cursor 网页登录」，再打开页面给出的官方授权链接，完成登录后点击「检查 Cursor 登录」。也可在展开区域填写自己的 Cursor API Key。连接开关保存在 SQLite，立即生效并跨重启保留，不必编辑代码或 .env。旧 FMJ_ALLOW_CURSOR 环境配置在尚无页面配置时仍兼容。macOS / Linux 目前使用官方安装器安装 CLI 后再检测连接。

网页操作需要本地会话令牌；不读取、展示或复制 Cursor 的登录密钥。网页登录凭证由 Cursor CLI 管理；手动填写的 Cursor API Key 只保存在当前后端进程内存，子进程通过环境变量接收，不放到命令行参数。断开只停用 FoundMyJob 的连接，不退出其他应用的 Cursor 账户。官方协议和可用额度由用户自己的账户决定。

生成仍使用只读 ask 模式和独立临时目录，禁止 Shell、文件读写、WebFetch 和 MCP；个人档案与岗位事实仅在用户确认生成后发送给所选服务。安装及连接不代表生成结果已核验。

官方依据：[Cursor 安装](https://cursor.com/docs/cli/installation)、[网页登录及 API Key](https://cursor.com/docs/cli/reference/authentication)。

## 自带 API Key 与免费模型

- 接口：DeepSeek、Kimi / Moonshot、豆包 / 火山方舟、Grok / xAI、Gemini、SiliconFlow、OpenRouter、Groq，固定官方 API 地址，避免把 Key 发到自定义未知端点。
- 用户在设置输入自己的 Key；只保存在**当前本机后端进程内存**，不写数据库、localStorage、导出或日志，重启后需重新输入。浏览器不通过接口读回完整 Key。
- 点击加载模型，从厂商获取最新列表；也可直接填写控制台模型 ID。豆包使用手工填写已开通的 Model ID 或推理接入点 ID。不会自动换厂商、模型或改用平台 Key。
- OpenRouter 可筛选实时价格中输入和输出均为零的模型；免费模式每次调用前重新核对价格，不满足就停止。仍受厂商速率、账户和服务可用性限制。
- SiliconFlow / Groq 有免费模型或 Free 账户方案，但列表不提供足够计费信息时不伪称当前账号一定免费。请使用页面上的官方价格与限额链接核实。
- API 适配器不读取开发者个人环境变量里的 Key，不内置任何共享 Key。

实际数据会发给你选择的厂商；生成前显示服务和模型并要求确认。失败不会悄悄回退到规则版或付费模型。

## FOB 自部署模型

自部署模型接入已预留并实现：在后端配置 `FMJ_SELF_HOSTED_BASE_URL`、`FMJ_SELF_HOSTED_MODEL` 和可选的 `FMJ_SELF_HOSTED_API_KEY`，即可选择「FOB 自部署模型」生成简历。支持兼容的 `/models` 与 `/chat/completions` 接口、连接检测、超时及输出上限配置。地址和服务密钥由部署者管理，不返回网页或 JSON 导出。配置示例和接口说明见 [自部署模型接入](docs/SELF_HOSTED_MODEL.md)。未配置时不会调用；当前本机访问限制、单任务生成和未开放计费的状态保持不变。

## 简历模板与证件照

当前提供 12 套模板：原有经典 ATS、校招清爽、现代商务、欧式模块、创意侧栏，以及国内端正规范、国内校招、国内现代履历、国际照片版、北美精简、英式雅致、资深专业。四套照片模板可显示独立上传的证件照，其余模板不显示照片。模板选择可展开／收起。

在简历工作室上传 JPG / PNG / WebP（最大 5 MB），在浏览器居中裁切为 300 × 420 JPEG，点击保存后与该简历一起写入数据库和版本记录。证件照不复用用户头像，也不发送给简历生成模型。照片修改会使审核失效；审核后的 PDF 打印包含照片，打印前等待图片解码。Markdown 导出保持文本，不嵌入照片。

模板目录包含稳定 ID、市场、照片支持、access、creditCost 和 entitlementKey；GET /api/resume-templates 返回模板及可用性，保存时后端核验权限。所有模板目前 access=free、creditCost=0；后续可通过服务端权益接入付费模板，当前没有购买、扣分或支付接口。本地客户端模板元数据不是可用于公网销售的完整授权系统。

## 平台积分与未来商业版

**平台积分入口被后端拒绝，暂不收款、不代付。** 客户端伪造余额或开启开关无法解锁。当前版本没有多用户注册和真实支付。

多人在线版需要独立实现用户认证、每个用户的加密凭证存储、支付回调验签和幂等、服务端额度预留／结算／退款账本及审计。平台服务不能挂载个人 Cursor 登录。届时数据库建议 PostgreSQL，按实际语义检索需求再加 pgvector；当前 SQLite 不需要向量库。

## 岗位数据范围

预置截图中的 36 家热门公司目录，以及 Figma、IMC、Tower Research Capital 的公开 Greenhouse 招聘板。热门公司支持点击筛选、单独同步和逐来源状态查看；目录与官网入口本身不计入岗位数。可以在设置添加其他 Greenhouse / Lever 企业板，同一来源的同步请求间隔至少 30 秒。

2026-10-15 实测：36 家热门公司中 34 家已接通，其中 33 家有具体职位；建信金科当前无开放报名岗位。阿里、华为、字节、蚂蚁、vivo、科大讯飞、联通、移动、蔚来、理想等均可同步真实列表。字节上限 10,000 条，飞猪／淘宝闪购按业务核验，分页重叠或有缺项时标部分同步并保留历史。Moka、联想、4399 等摘要记录会明确提示查看原文。当前本机有 38759 条可浏览岗位。

每家公司当前的数量、限制和后续工作见 [招聘来源接入记录](docs/JOB_SOURCES.md)。来源可能随时变更；“已同步”表示成功读取该适配器覆盖的公开列表，不表示覆盖公司全部招聘渠道，也不保证申请时仍在招。

发现页默认使用已保存画像的国家、城市与办公方式筛选，工作台推荐与热门公司匹配使用相同偏好。岗位库仍可临时调整条件、「恢复画像偏好」或「查看全部库内岗位 / 清除筛选」，不会因为零结果自动回退到其他地区。排序可选匹配度或最近同步；每批默认显示 25 条，可选 50 条，向下滚动时自动追加下一批，也可点击「继续加载」。切换筛选或排序后从所选批次大小重新展示。用户勾选「仅显示目标职位」才启用标题筛选。热门公司默认收起，点击标题展开后，上方按公司筛选岗位，下方提供招聘官网入口。两处共用同一份按画像范围筛选的目录：国内显示 36 家公司，国外显示 129 家去重企业／机构，全球显示 165 家；国外包含 10 个求职行业各 6 家世界500强企业、七国各 5 家投资机构和 5 家银行求职精选，以及原有三个招聘板；标题和公司数量随之更新。可按加拿大、美国、日本、英国、法国、澳大利亚、新加坡及行业／机构类型筛选，公司卡片、岗位数、下方岗位与官网入口同步更新。公司目录不代表该公司当前在所选国家有空缺。仅有官网入口的公司显示「尚未接入岗位源 · 官网查看」，已接入招聘源的公司可单独同步。切换画像或保存偏好后重新应用该画像条件（包括同一国家内的城市或办公方式变化）；普通刷新数据保持临时筛选。热门公司展开后展示最多 10 个真实匹配岗位，要求标题匹配目标职位或至少两项画像技能相同，并满足当前国家、城市和办公方式条件；无结果时说明这是本地已收录范围，并提示检查公司筛选或搜索官方来源。办公方式未注明的岗位默认保留并标注「未注明」，不额外提供包含未注明岗位的勾选项；明确 Hybrid 等不同办公方式的相关岗位单独展示，国家、城市和公司条件保持不变，精确结果与相关推荐合计最多 10 条。发现页仅保留结果数量与已显示数量。工作台集中展示求职统计、求职路径与推荐机会，不展示岗位库概览；卡片随窗口宽度与数量自然排布，暂无推荐时显示简短的操作提示。

画像提供「国内／国外／国内外均考虑」三种招聘地点范围，对应 searchScope=domestic/overseas/all。旧画像按 market 自动推断范围（cn→国内，ca/us/other→国外，空值→均考虑），读取时保留旧数据；保存新范围后持久记录。画像提供国家、城市、办公方式的中英文选项，以及其他城市填写入口和原有备注。jobPreferences 保存独立的 country/city/work 值；旧的「Toronto，onsite」等明确备注在读取时自动识别，原文保留不重写。明确选择优先于旧备注，国家会同步招聘地点范围和 market；服务端校验国家、城市一致性和办公方式枚举。办公方式未注明的岗位不假定为现场办公。国外名单及选择依据见 [国外公司目录](docs/OVERSEAS_COMPANIES.md)。金融机构按求职知名度精选，不宣称官方前五排名；新增目录以官网入口为主，不等同于接通自动同步。

官网检索发现的具体岗位可通过 POST /api/jobs/import（discoveredFromWeb: true）与真实摘要和原文链接一起入库，sourceKind=discovered、verificationStatus=pending、descriptionKind=summary；与企业接口和手动导入分别计数，同一原文 URL 去重。检索岗位可以搜索、排序、收藏和查看详情，标注待核验及摘要；不伪称已经确认在招，也不会因为其他招聘板同步被清除。JSON 导出保留来源属性。

快手公开列表仍有访问校验，交银金科官网连接超时且旧专题无法核验在招状态，显示“待接通”及官网入口。建信金科显示“当前公开列表暂无岗位”，不把已截止的校招计为在招。所有公司都已配置本地品牌图标。失败保留上次成功数据；服务中断后可重新同步。Windows 上的少数旧 TLS 官网通过系统自带 curl 保持证书校验，不禁用 HTTPS 校验。

招聘状态、薪资、年限、资格以原文为准。招聘类型只对标题明确标示实习／应届或资深级别的岗位推断，其余标「未注明」；技能与地区提取是启发式匹配，并非 AI 筛选结论。匹配度不代表录用概率。国内岗位不是全网覆盖，未接入网站支持手动导入 JD，不绕过登录或验证码。

参考：[Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html)、[Lever Postings API](https://github.com/lever/postings-api)、[OpenRouter 模型列表](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。

## 数据库与备份

本机文件 `.runtime/foundmyjob.sqlite`，采用 WAL、外键、事务和版本冲突检查。表包括 profiles（画像）、config（非敏感设置）、sources、jobs、saved、resumes、resume_versions、applications、tasks。数据库结构版本为 2，旧数据在一个事务内迁移；API 数据快照版本为 3。

关闭服务后复制数据库文件做完整备份；运行中的数据库请勿仅复制主文件而忽略 WAL。恢复时关闭服务，再用备份替换主文件。页面的 JSON 导出用于查阅／迁移，当前没有 JSON 自动恢复接口。Git 忽略整个 `.runtime/`、`.env*`（除模板）、SQLite 文件及 `.cursor/`。

此版本不提供磁盘加密；数据库属于你的本地个人文件，包含经历和联系方式。不要把运行目录或整盘压缩包当作源代码分享。

## API 与验证

开发规划文档（2026-10-29）：[功能开发建议清单](docs/FoundMyJob_功能开发建议清单.docx)、[前后端开发任务名称与描述](docs/FoundMyJob_前后端开发任务名称与描述.docx)。这些文档记录后续功能建议，不代表功能均已实现。

2026-10-15 的阶段成果先提交到 `main`，作为后续开发基线。下一阶段从 `main` 创建 `dev`，日常开发和阶段性提交在 `dev` 上进行；完成自动测试、关键页面与真实接口验证后，再合并回 `main`。本地数据库、画像、简历、登录信息及 `.env.local` 保留在本机，不随源码提交。

- `GET /api/state`：读取本机数据和本地会话令牌，包含独立的 `user` 信息和 `profiles` 列表，不含 Key。
- `POST /api/user`：保存 `username`、`avatar` 和 `revision`；头像为空字符串表示移除，多窗口版本冲突返回 409。
- `POST /api/profiles/basics`：用户中心保存当前画像的基础信息、技能和偏好，带 `id`、`revision`；拒绝教育、工作、项目经历等额外字段，原有经历保持不变。
- `POST /api/profiles/create`：用 `label`、`market`、`resumeLanguage` 新建画像，可传 `copyFrom` 复制已有画像，返回 `createdProfileId`。
- `POST /api/profiles/save`（或 `/api/profile`）：保存完整画像字段，必须带 `id`、`revision` 防止覆盖其他画像或较新的修改。
- `POST /api/profiles/archive`：带 `id`、`revision`、`archived` 归档或恢复画像。
- `GET /api/cursor/status`、`POST /api/cursor/connect`、`/api/cursor/install`、`/api/cursor/login`、`/api/cursor/key`、`/api/cursor/disable`：页面内检测、安装、登录和配置本机连接；需要会话令牌。
- `POST /api/settings`：保存非敏感设置，带 `revision` 防覆盖。
- `POST /api/credentials`：设置／清除内存中的个人 Key。
- `GET /api/models?provider=...`：加载对应厂商模型。
- `POST /api/jobs/search`：按关键词或画像目标职位查询 BMO、TD Bank、RBC、CIBC 的官方 Workday 招聘源，也可传 `sourceId` 搜索单一已接入来源。只发送职位关键词，不发送个人经历、姓名、邮箱等画像内容。
- `POST /api/jobs/sync`：同步招聘源；传海外画像 `profileId` 时优先限定已接入海外来源，也可传 `sourceId` 只同步一家公司。`GET /api/state` 中的 `syncing` 和各来源状态用于显示进度；多个来源最多并发 3 个。
- `POST /api/jobs/import`、`/api/sources`：导入真实 JD、添加 Greenhouse / Lever 招聘源。
- `POST /api/generate`：必须带 `profileId`、`profileRevision`、`jobId`，请求幂等生成任务；可覆盖画像默认语言。`GET /api/tasks/:id` 查看结果。
- `POST /api/applications`：带 `jobId`、`profileId` 添加投递计划，同一岗位不同画像分别跟踪。
- `POST /api/resumes/save`：编辑／审核，并可保存 layout 与 photo；`/api/applications/status`：手动记录投递状态。

变更接口要求 JSON、同源 Host/Origin、`X-FMJ-Token`；不开放 CORS。

### 海外官网职位搜索（2026-10-16）

已接入 BMO、TD Bank、RBC、CIBC 的公开 Workday 招聘列表。「搜索岗位库」仅在已收录岗位中筛选，不等待官网请求；热门公司内点击「搜索官网岗位」才会查询官网并将岗位写入同一岗位库。公司/地点/办公方式筛选继续在本机执行。

官网查询与本地筛选共用常见职位的中英文别名：例如搜索「数据工程师」「数仓工程师」或 `Data Engineer`，均能保留已收录的中英文数据工程职位。附带 Senior、公司名或额外技能的搜索词保留原有限定；国家、城市、公司和办公方式条件继续生效。按匹配度排序时，目标职位名称匹配的岗位优先于仅有技能交集的岗位。

Workday 每家公司每次最多读取 200 条关键词结果，优先为目标职位获取最多 80 条完整详情；其余明确标为职位摘要。后续页的 total=0 不代表没有后续结果。结果按稳定 ID 去重，查询快照始终标注部分覆盖，失败不清空之前收录的岗位；明确不可申请或已过截止日期的已读取职位会被排除。办公方式仅从官方字段或明确的工作模式描述读取，不把 hybrid cloud 当成混合办公。目录中其余未接入企业不会显示成「该公司没有岗位」。

## 同步进度

同步和官网搜索使用最多 3 个并发来源，任一来源完成后立即处理下一个，慢来源不再阻塞同批的其他位置。进度卡片仅保留标题、实际处理来源数、百分比、进度条、已用时间、已读取岗位数和成功／失败统计。百分比按处理完毕的来源数计算，失败也计入已处理；不代表时间进度。向下滚动至顶部进度卡片离开视野时，页面底部显示半透明小进度条；滚回顶部后自动隐藏。同步结束后两处进度显示平滑淡出并移除，不保留完成状态卡片；系统开启减少动态效果时直接移除。详细来源状态可在 AI 与数据设置查看。单来源官网分页与详情请求仍受官网响应、限流和各适配器超时限制。

普通搜索直接使用已加载的岗位库，国内外一致，不发起官网抓取；匹配排序对每个岗位在单次搜索中只计算一次匹配度。发现页同步遵循当前国内／国外范围（未指定地区时同步全部），选中公司时只更新该来源；未知范围的自定义招聘板继续保留。设置页「同步所有岗位源」仍可更新全部来源。

OCR 使用 [Tesseract.js](https://github.com/naptha/tesseract.js) 和随 npm 依赖安装的中英文语言包；PDF 本地渲染使用 PDF.js 与 @napi-rs/canvas。
